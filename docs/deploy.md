# نصب نِویس روی سرور خودتان

> **وضعیت واقعی فعلی (۲۰۲۶-۱۱-۲۲):** نِویس جدید روی `vexor-server` و روی دامنهٔ `https://nevis.manaz.pro` بالاست. نصب با `deploy/first-deploy.sh` انجام شد: ایمیج `nevis-next:0.1.0` (ساخته‌شده از بستهٔ release بدون base image، چون رجیستری‌های Docker از این Mac در دسترس نبودند) در `/opt/nevis` با compose، داده در `/var/lib/nevis`، روی شبکهٔ `nevis-beta-ingress` که Traefik از قبل به آن وصل بود؛ مسیر دامنه در Coolify (پروکسی ← Dynamic Configurations ← `nevis-public-beta.yaml`) به `http://nevis-app-1:8787` اشاره می‌کند. نِویس قدیمی (کانتینر، ایمیج، داده و فایل‌های سرویس) با `deploy/remove-old.sh` و بدون بکاپ، به خواستهٔ مالک، پاک شد. کد جدید روی شاخهٔ `nevis-next` همین مخزن است؛ tagهای انتشار `nx/vX.Y.Z`.


**وضعیت این مستند (صادقانه).** مراحل «ساخت بسته، سرور با کد دعوت، ثبت‌نام، نوشتن، بکاپ و بازگردانی روی سرور تازه» را **روی همین Mac با یک سرور محلی تمرین کرده‌ام** (`node tools/deploy-rehearsal.mjs`، نتیجه: `REHEARSAL OK`). نصب با **systemd، Caddy و Docker و HTTPS واقعی روی یک ماشین لینوکس را هنوز اجرا نکرده‌ام**؛ فایل‌هایشان آماده است ولی اولین بار که روی سرور شما بالا بیاید ممکن است یک اصلاح کوچک لازم شود. اگر چیزی نشد، خروجی `journalctl -u nevis` را برایم بفرستید.

## چه چیزی لازم دارید
- یک ماشین لینوکس (x86 یا ARM) با دسترسی root، و **یک دامنه** که DNS آن به این ماشین اشاره کند. بدون HTTPS برنامه کار نمی‌کند (مرورگر برای قفل چندتبی و ذخیره‌سازی پایدار به «secure context» نیاز دارد).
- پورت‌های ۸۰ و ۴۴۳ باز.
- یک جای دیگر (دیسک دوم، ماشین دیگر) برای نسخهٔ پشتیبان.

## ۱) ساخت بسته (روی Mac)
```bash
deploy/build-release.sh v0.1
```
خروجی: `release/nevis-v0.1.tar.gz` شامل `web/` (خود برنامه)، `bin/nevis-server-linux-amd64` و `…-arm64` (سرور، یک فایل)، و فایل‌های نصب (`nevis.service`، `Caddyfile`، `docker-compose.yml`، `Dockerfile`، `env.example`، `backup.sh`).

## ۲) نصب با systemd و Caddy (پیشنهادی)
روی سرور (جای `amd64` را با معماری خودتان عوض کنید):
```bash
tar xzf nevis-v0.1.tar.gz && cd nevis-v0.1
sudo useradd --system --home /var/lib/nevis --shell /usr/sbin/nologin nevis
sudo install -d -o nevis -g nevis /var/lib/nevis
sudo install -d /opt/nevis/bin /etc/nevis
sudo install -m 755 bin/nevis-server-linux-amd64 /opt/nevis/bin/nevis-server
sudo cp -R web /opt/nevis/web
sudo cp env.example /etc/nevis/env && sudo chmod 600 /etc/nevis/env
sudo nano /etc/nevis/env          # SESSION_SECRET (openssl rand -hex 32)، INVITE_CODES و بقیه
sudo cp nevis.service /etc/systemd/system/ && sudo systemctl daemon-reload
sudo systemctl enable --now nevis
curl -s http://127.0.0.1:8787/v1/health     # باید ok:true بدهد
```
Caddy (گواهی HTTPS را خودش می‌گیرد): `Caddyfile` را با دامنهٔ خودتان ویرایش و در `/etc/caddy/Caddyfile` بگذارید، سپس `sudo systemctl reload caddy`. اگر از nginx استفاده می‌کنید، شرط مهم این است که **سربرگ `Host` بدون تغییر به سرور برسد** (سرور `Origin` را با `Host` مقایسه می‌کند) و حجم بدنه تا `MAX_BLOB_MB` مجاز باشد.

**ثبت‌نام.** سرور با `REGISTRATION=invite` فقط کسی را می‌پذیرد که یکی از کدهای `INVITE_CODES` را داشته باشد. اولین حساب را خودتان بسازید (کد دعوت را در فرم ثبت‌نام بزنید)، **کلید بازیابی** را جای امن بنویسید (فقط یک بار نشان داده می‌شود)، و کد را بعد از استفاده از فهرست بردارید. هیچ‌وقت `REGISTRATION=open` را روی اینترنت نگذارید.

## ۳) نصب با Docker (جایگزین)
```bash
cp deploy/env.example deploy/.env && nano deploy/.env
docker compose -f deploy/docker-compose.yml up -d --build
```
داده در یک volume به نام `nevis-data` می‌ماند؛ سرور فقط روی `127.0.0.1:8787` گوش می‌دهد و باز هم به Caddy/nginx جلوی آن نیاز دارید.

## ۴) بکاپ و بازگردانی
- سرور خودش **روزی یک‌بار** (و یک بار بلافاصله بعد از راه‌اندازی) از پایگاه‌داده نسخهٔ کامل و سازگار در `DATA_DIR/backup` می‌گیرد و **۱۴ نسخهٔ آخر** را نگه می‌دارد. این‌ها روی همان دیسک‌اند؛ پس کافی نیستند.
- برای بیرون از ماشین، هر شب با cron:
  ```bash
  0 3 * * *  NEVIS_BIN=/opt/nevis/bin/nevis-server /opt/nevis/backup.sh /var/lib/nevis /mnt/backups/nevis
  ```
  (`backup.sh` را کنار برنامه بگذارید.) این دستور یک نسخهٔ تازه از پایگاه‌داده و پیوست‌ها را، **در حالی که سرور کار می‌کند**، کپی می‌کند. پیوست‌ها با نام محتوایشان ذخیره می‌شوند و فقط اضافه می‌شوند.
- **بازگردانی** روی ماشین تازه: پوشهٔ `DATA_DIR` را بسازید، `nevis.db` از پوشهٔ بکاپ را همان‌جا و پوشهٔ `blobs` را کنارش بگذارید، سرور را با همان `env` بالا بیاورید. حساب‌ها، فضاهای کاری و نشست‌ها همان‌اند و دستگاه‌ها ادامه می‌دهند. این مسیر را در تمرین بالا امتحان کرده‌ام.

## ۵) به‌روزرسانی
بستهٔ تازه را بسازید، `bin/nevis-server` و `web/` را جایگزین کنید و `sudo systemctl restart nevis`. داده دست‌نخورده می‌ماند. اگر نسخهٔ تازه قالب داده را عوض کرده باشد، دستگاهی که برنامهٔ قدیمی دارد پیام «برنامه را به‌روز کنید» می‌گیرد و چیزی خراب نمی‌شود.

## ۶) برنامهٔ دسکتاپ
در اولین اجرا آدرس سرور (`https://دامنهٔ-شما`) را وارد کنید؛ بقیه مثل وب است.

## چیزهایی که باید بدانید
- **رمزنگاری سرتاسری نیست.** سرور محتوای یادداشت‌ها را می‌بیند و روی دیسک‌اش ذخیره می‌کند؛ از آن مثل سرور خودتان محافظت کنید (دیسک رمزشده، دسترسی SSH محدود).
- **سرویس‌ورکر هنوز نیست**: اولین بارگذاری برنامه اینترنت می‌خواهد؛ بعد از آن یادداشت‌ها آفلاین کار می‌کنند ولی بازکردن دوبارهٔ برنامه بدون شبکه تا آمدن سرویس‌ورکر (M15) مطمئن نیست.
- **یک سرور، یک ماشین.** همگام‌سازی چندسروره و همکاری چندنفره (اعضا و دسترسی) در نسخهٔ اول نیست.
- نمای تقویم، نمودار، فرم و داشبورد پایگاه‌داده هنوز نیستند (جدول و برد هستند).
- حذف خودکار سطل زباله نیست؛ خودتان خالی می‌کنید.

## فهرست بررسی امنیتی پیش از دادن آدرس به کسی
- `SESSION_SECRET` تصادفی و حداقل ۳۲ نویسه؛ `/etc/nevis/env` با دسترسی ۶۰۰.
- `REGISTRATION=invite` و کدهای دعوت مصرف‌شده حذف شده‌اند.
- فقط Caddy/nginx از بیرون در دسترس است؛ پورت ۸۷۸۷ روی `127.0.0.1` می‌ماند.
- بکاپ بیرونی کار می‌کند و **یک بار روی ماشین تازه بازگردانده شده** (با همان مراحل بند ۴).
