# قالب رکوردهای ساختاریافته v1 (`sv = 1`)

مرجع پیاده‌سازی: `packages/core/src/records.ts`. مبنا: ADR-0002 و ADR-0004. همهٔ رکوردها **فیلدهای تخت** (رجیستر LWW با HLC) روی یک موجودیت‌اند؛ مجموعه = یک فیلد per عنصر؛ هیچ آرایه‌ای در فیلد همگام‌شونده نیست مگر مقدار اتمی کل (`config`). `$kind` و `createdAt` در اولین op نوشته می‌شوند.

## موجودیت‌ها
| `$kind` | فیلدها | بدنهٔ Yjs |
|---|---|---|
| `page` | `title`، `parent` ('' = ریشه)، `sortKey`، `trashed`، `kind` (`"doc"`)، `createdAt`، `trashedAt` (میلی‌ثانیه؛ همراه `trashed:true` در همان op نوشته می‌شود و با بازگردانی `null` می‌شود؛ ساخت‌های قدیمی‌تر آن را نمی‌نویسند و نمی‌خوانند)، `tag:<tagId>` (`true`/`false`) | دارد |
| `database` | همانند page (گره‌ای از درخت صفحه است) | دارد (توضیح) |
| `property` | `db`، `name`، `type`، `config`، `sortKey`، `trashed`، `createdAt`، `opt:<optionId>` (فقط select/multiSelect) | ندارد |
| `view` | `db`، `name`، `type` (`table` یا `board`)، `config`، `sortKey`، `trashed`، `createdAt` | ندارد |
| `row` | `db`، `sortKey`، `trashed`، `createdAt`، `c:<propId>`، `c:<propId>/<elemId>` | دارد (`rowId == bodyDocId`) |
| `tag` | `name`، `color`، `createdAt` | ندارد |
| `savedSearch` | `name`، `query`، `sortKey`، `trashed`، `createdAt` | ندارد |
| `settings` | یک فیلد per تنظیم (نام تنظیم = نام فیلد)؛ شناسهٔ موجودیت = شناسهٔ workspace | ندارد |

`id` همیشه UUIDv7 (رشته). `sortKey` = fractional index + پسوند تصادفی ۴ نویسه؛ ترتیب همه‌جا `(sortKey, id)` (در تساوی هم ترتیب یکسان است).

## نوع propertyها و شکل مقدار سلول
| `type` | سلول (روی ردیف) | `config` ی property | یادداشت |
|---|---|---|---|
| `text` | `c:<propId>` = رشته یا `null` | `{}` (برای ستون عنوان `{"title":true}`) | متن بلند هم رشته؛ متن هم‌زمان باید در بدنهٔ ردیف (Yjs) باشد |
| `number` | `c:<propId>` = **رشتهٔ اعشاری** یا `null` | `{}` | هرگز JSON number نیست (پایین) |
| `date` | `c:<propId>` = `"2026-11-20"` یا `"2026-11-20T08:30:00.000Z"` یا `null` | `{}` | میلادی؛ نمایش شمسی فقط UI |
| `select` | `c:<propId>` = شناسهٔ گزینه یا `null` | — | گزینه‌ها: `opt:<optionId>` روی property = `{"name","color","sortKey"}` یا `null` (حذف‌شده) |
| `multiSelect` | `c:<propId>/<optionId>` = `true`/`false` (یک رجیستر per عنصر) | — | ترتیب نمایش = ترتیب گزینه‌ها |
| `relation` | `c:<propId>/<rowId>` = `true`/`false` | `{"target":"<dbId>"}` | یک‌طرفه؛ backlink مشتق است (`backlinks()`) و ذخیره نمی‌شود |
| `checkbox` | `c:<propId>` = `true`/`false` | `{}` | |
| `url` | `c:<propId>` = رشته یا `null` | `{}` | |

`null` در مقدار فیلد = «خالی شده» و یک نوشتن واقعی با HLC است (ADR-0004 بند ۶).

### ستون عنوان
ADR-0002 فیلد `title` برای ردیف ندارد؛ پس `createDatabase` یک property از نوع `text` با `config: {"title": true}` می‌سازد و عنوان ردیف = مقدار آن سلول. اگر چند property عنوان‌دار باشد، **اولین عنوان‌دارِ غیرحذف‌شده** به ترتیب `(sortKey, id)` و اگر هیچ‌کدام عنوان‌دار نباشد، **اولین property غیرحذف‌شده** به همان ترتیب عنوان است؛ پس روی همهٔ دستگاه‌ها یکسان است.

## عدد (`normalizeDecimal`) — `packages/core/src/decimal.ts`
خروجی: ارقام ASCII، `-` اختیاری، `.` اختیاری، بدون توان؛ صفرهای ابتدایی حذف، صفرهای انتهایی **حفظ** (`"12.50"` همان می‌ماند)، «-0» ندارد. ورودی:
- ارقام `۰-۹` و `٠-٩` ← `0-9`؛ LRM/RLM/ALM/ZWNJ/ZWSP و فاصلهٔ دو سر حذف؛ `−` (U+2212) منفی؛ `+` ابتدایی حذف.
- جداکنندهٔ اعشار: `٫` (U+066B) یا `.`. **`/` اعشار نیست** (`1/2` کسر است، نه ۱٫۲): رد می‌شود.
- `٬` (U+066C)، `,` و `،` فقط **جداکنندهٔ هزارگان** هستند و فقط در گروه‌بندی درست پذیرفته می‌شوند (گروه اول ۱–۳ رقم، بقیه دقیقاً ۳): `1,234` ← `1234`؛ `1,5` ← **رد** (۱٫۵ یا ۱۵؟).
- هر چیز دیگر (توان، حروف، دو نقطه، خالی، بیش از ۱۰۰ نویسه) رد می‌شود. رد قابل اصلاح است؛ برداشت اشتباه بی‌صدا نیست.
- `compareDecimal` مقایسهٔ دقیق بدون float.

## تاریخ (`normalizeDate`) — `packages/core/src/dates.ts`
ورودی: میلادی `YYYY-MM-DD` یا `YYYY/MM/DD`، ISO با `Z`، ارقام فارسی؛ **سال ۱۲۰۰–۱۶۹۹ شمسی فرض می‌شود** (هیچ تاریخ میلادی‌ای که کسی می‌نویسد در این بازه نیست) و به میلادی تبدیل می‌شود. روز نامعتبر (`2026-02-30`، `1404/12/30` در سال غیرکبیسه) رد می‌شود. تبدیل با `Intl` (تقویم persian) انجام می‌شود، همان منبعی که UI نمایش می‌دهد؛ آزمون: رفت‌وبرگشت ۱۳۰ سال روز به روز. نمایش تاریخ بی‌ساعت بدون منطقهٔ زمانی محلی (UTC) است تا روز جابه‌جا نشود.

## نماها (view) و `config` (M8b)
`view.type` = `table` یا `board`؛ `view.config` یک مقدار JSON **کامل** است (LWW کل مقدار). شکل نسخه‌دار و **بردبار** (`packages/core/src/viewConfig.ts`):
```json
{ "v": 1, "presentation": "list", "groupBy": "<propId>", "sort": [{ "prop": "<propId>", "dir": "asc" }], "hidden": ["<propId>"], "columnOrder": ["<propId>"], "frozenThrough": "<propId>", "columnWidths": { "<propId>": 320 }, "filter": [{ "prop": "<propId>", "op": "contains", "value": "x" }] }
```
| فیلد | معنا | پیش‌فرض/بردباری |
|---|---|---|
| `v` | نسخهٔ شکل config (عدد صحیح) | نوشتن هیچ‌وقت آن را کم نمی‌کند؛ `v` بزرگ‌تر تا جایی که فهمیده شود خوانده می‌شود |
| `presentation` | چیدمان `list` یا `gallery` برای نمای `table` | مقدار خالی یا ناشناخته نمای جدول را باز می‌کند. نسخه‌های قدیمی همین ردیف‌ها را به شکل جدول نشان می‌دهند |
| `groupBy` | شناسهٔ property از نوع `select` (ستون‌های board = گزینه‌های آن) | `''`: اگر property نباشد، حذف شده باشد یا select نباشد = بدون گروه‌بندی |
| `sort` | قواعد مرتب‌سازی به ترتیب اولویت؛ عدد دقیق (رشتهٔ اعشاری)، متن با ترتیب فارسی، تاریخ، تیک (false قبل از true)، select به ترتیب گزینه | قاعده‌ای که property آن نیست حذف می‌شود؛ `dir` نامعتبر = `asc`؛ **سلول خالی همیشه آخر** (در هر دو جهت)؛ ترتیب برابرها = ترتیب خود ردیف‌ها `(sortKey, id)` |
| `hidden` | property‌هایی که نمایش داده نمی‌شوند | شناسه‌ای که property آن نیست حذف می‌شود |
| `columnOrder` | ترتیب ستون‌ها در جدول | شناسه‌های تکراری و حذف‌شده نادیده گرفته می‌شوند؛ ستون‌های تازه در انتها می‌آیند |
| `columnWidths` | عرض ستون‌ها بر حسب پیکسل، با کلید شناسهٔ property | مقدار نامعتبر، خارج از بازهٔ ۱۲۰ تا ۱۰۰۰ یا property حذف‌شده نادیده گرفته می‌شود؛ نبود مقدار یعنی عرض پیش‌فرض |
| `frozenThrough` | ثابت کردن ستون‌ها تا این property | شناسهٔ خالی یا حذف‌شده یعنی هیچ ستونی ثابت نیست |
| `filter` | شرط‌هایی که همه باید برقرار باشند: `op` یکی از `contains، not_contains، is، is_not، gt، lt، empty، not_empty، checked، unchecked`؛ `value` متن (برای select شناسهٔ گزینه؛ عدد با مقایسهٔ دقیق اعشاری) | قاعدهٔ property حذف‌شده یا `op` ناشناخته هنگام خواندن حذف می‌شود (نسخهٔ config تغییر نکرد: فیلد تازه است و ساخت‌های قدیمی‌تر آن را نادیده می‌گیرند و حفظ می‌کنند) |
- فیلد ناشناخته (که ساخت نو نوشته) خوانده نمی‌شود ولی هنگام بازنویسی توسط این ساخت **حفظ می‌شود** (`patchViewConfig`).
- هر چیز ناخواناپذیر (غیر شیء، نوع غلط) = پیش‌فرض؛ هیچ‌وقت exception نیست.
- **جابه‌جایی کارت در board** (`moveCard`): مقدار select **و** `sortKey` ردیف در **یک op** نوشته می‌شوند (مثل `movePage`)، پس با هم برنده یا بازنده‌اند. ستون «بدون مقدار» برای ردیفی است که گزینه‌اش خالی یا حذف‌شده است.
- جست‌وجوی داخل پایگاه‌داده فقط روی همین دستگاه است (در config نوشته نمی‌شود)؛ ویرایش هم‌زمان config دو دستگاه همچنان «یکی برنده» است (کل مقدار).

## قاعدهٔ تعارض (خلاصه) و موارد غافل‌گیرکننده
| وضعیت | نتیجه |
|---|---|
| دو افزودن هم‌زمان گزینهٔ select | هر دو می‌مانند (`opt:<id>` متفاوت) |
| دو ویرایش هم‌زمان دو ستون یک ردیف | هر دو می‌مانند |
| دو ویرایش هم‌زمان **یک** سلول | HLC بزرگ‌تر |
| **تغییر نام و تغییر رنگ هم‌زمان یک گزینه** | **یکی کل از دست می‌رود** (کل مقدار `opt:<id>` یک رجیستر است) |
| تغییر نام گزینه‌ای که هم‌زمان حذف شد | اگر HLC تغییر نام بزرگ‌تر باشد گزینه برمی‌گردد (کل مقدار نوشته می‌شود) |
| فیلتر و مرتب‌سازی هم‌زمان در `config` یک نما | یکی از دو (کل مقدار) |
| افزودن و حذف هم‌زمان **همان** عنصر multi-select | HLC بزرگ‌تر برنده است (add-wins نیست) |
| حذف (trash) ردیف/ستون/پایگاه | فقط پنهان می‌کند؛ سلول‌ها و ردیف‌ها دست‌نخورده می‌مانند (cascade نیست) |
| حذف گزینه‌ای که سلولی هنوز به آن اشاره دارد | سلول همان شناسه را نگه می‌دارد؛ UI گزینه‌ای نشان نمی‌دهد |
| ردیفی که پایگاه‌اش (هنوز) نرسیده | در نما نیست |
| سلول با شکل ناجور (مثلاً عدد JSON در ستون متن) | خالی خوانده می‌شود |
| `type` ناشناخته در property | به‌عنوان `text` خوانده می‌شود |
| چرخهٔ درخت (A زیر B و B زیر A) | در نما، صفحه‌ای که `parent` آن HLC بزرگ‌تری دارد به ریشه می‌رود؛ دادهٔ ذخیره‌شده عوض نمی‌شود |

## چه چیزی از مدل قدیمی (`spike/tiptap/src/database/model`) در این مدل **جا نمی‌شود** (ساخته نشد)
۲۵ نوع قدیمی در برابر ۸ نوع جدید. نیامده‌ها:
- **انواع:** `status`، `people`، `files`، `email`، `phone`، `place`، `verification`، `connected`، `rollup`، `formula`، `created_time`، `created_by`، `last_edited_time`، `last_edited_by`، `button`، `unique_id` (فرمول/rollup/workflow طبق ROADMAP خارج از دامنه‌اند؛ `files` با M9؛ `created*`/`last_edited*` را می‌توان از HLC/`createdAt` مشتق کرد).
- **سلول متن غنی** (`runs` با bold/italic/لینک/mention): اینجا متن ساده؛ متن غنی = بدنهٔ ردیف (Yjs).
- **تاریخ:** بازه (`end`)، منطقهٔ زمانی ذخیره‌شده، حالت `datetime` با `timeZone`.
- **ساختار:** `Source` و `Container` (چند منبع برای یک پایگاه، `presentation: inline|full`، `hostPageId`، `sourceLinks`)، `Definition` مشترک بین منبع‌ها، `description` ستون، `RecordMeta` per رکورد (`revision`، `updatedBy`، `lastOperationId`...)، حذف نرم با `deletedAt`.
- **عدد:** `number` قدیمی JSON number بود؛ اینجا رشتهٔ اعشاری.
اگر هر کدام لازم شد، با ADR و `sv+1` اضافه می‌شود.
