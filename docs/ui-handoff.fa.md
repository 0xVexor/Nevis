# تحویل و ادامهٔ بازسازی UI روی سیستم دیگر

یادداشت انتشار: کاربر اکنون commit و push همین مرحله را درخواست کرده است. پس از انتشار شاخهٔ `feature/ui-foundations-spec`، برای ادامه روی سیستم خانه `git fetch origin` و سپس `git switch --track origin/feature/ui-foundations-spec` را در clone بدون تغییر محلی اجرا کنید (اگر شاخه از قبل وجود دارد، همان شاخه را switch و با `git pull --ff-only` به‌روز کنید). توضیحات «هنوز commit/push نشده» در پایین این سند، سابقهٔ مرحلهٔ آماده‌سازی‌اند؛ وضعیت واقعی را از Git بگیرید. نسخهٔ dev همچنان جداست و این انتشار به معنی merge به dev نیست. تست و build این مرحله به درخواست کاربر اجرا نشده‌اند.

تاریخ ثبت: ۲۰۲۶-۱۱-۰۲. ابتدا `CLAUDE.md`، سپس `docs/ui-design-language.fa.md` و `docs/design-system.md` خوانده شوند. سند تاریخی معماری: `docs/ui-foundations-plan.md`؛ وضعیت فعلی این سند بر توضیحات تاریخی آن مقدم است.

## وضعیت واقعی کد

شاخهٔ فعلی `feature/ui-foundations-spec` است؛ مبنا و HEAD برابر `51913923e7e6a70289afc3b04672b335718537e9` از dev است. تغییرات فعلاً commit، push یا merge نشده‌اند. صرف checkout کردن این نام شاخه روی سیستم دیگر، تغییرات را منتقل نمی‌کند.

**به درخواست کاربر تست، build و بررسی مرورگر اجرا نشود مگر دوباره درخواست کند. آخرین اصلاحات تست نشده‌اند.** موفقیت بررسی‌های مراحل قبلی تأیید نسخهٔ فعلی نیست. عملیات بومی Tauri و اجرای واقعی macOS نیز تأیید نشده‌اند.

## انتقال بدون push

بستهٔ `nevis-ui-handoff.zip` همراه این تحویل، patch تغییرات tracked و فایل‌های جدید را دارد؛ مخزن کامل، dependencies، vault و تنظیمات مرورگر داخلش نیستند. آن را در پوشه‌ای جدا از مخزن extract کنید و README آن را دنبال کنید. روی clone تمیزِ همان commit مبنا اعمال کنید؛ روی تغییرات محلی دیگر بی‌بررسی اعمال نشود. پس از انتقال می‌توان تغییرات را با جریان Git پروژه commit و به dev پیشنهاد کرد.

پورت‌ها و localStorage به سیستم دیگر منتقل نمی‌شوند. نمونه‌های مقایسه‌ای ۴۱۷۸/۴۱۸۰ بیرون از ریپو هستند و برای ادامهٔ این مرحله لازم نیستند؛ منبع مرجع Settings اکنون داخل ریپو است.

## راه‌اندازی وب روی سیستم خانه

Git، Node.js و npm متناسب با پروژه نصب باشند. داخل clone و پس از اعمال بسته:

```powershell
cd spike/tiptap
npm ci
npm run dev:settings
```

نمونهٔ مرجع: `http://127.0.0.1:4182/settings-preview.html`.
برای محصول، در ترمینال جدا از همان پوشه:

```powershell
npm run dev -- --host 127.0.0.1 --port 4184 --strictPort
```

محصول: `http://127.0.0.1:4184/`؛ Settings را از برنامه باز کنید. این دستورها فقط راه‌اندازی‌اند؛ تست یا build را خودکار اجرا نکنید. نسخهٔ وب جای محیط بومی Tauri برای بکاپ و اتصال‌های desktop نیست.

## تغییرات پوستهٔ اصلی در همین نشست

هویت بالای فضای کار و Settings اکنون از WorkspaceHeader مشترک استفاده می‌کند. workspace switcher زیر لوگو آمده؛ سطح‌های اصلی تخت و هم‌زبان Settings شده‌اند. New page پنج عمل واقعی قبلی را حفظ می‌کند. حالت Icons only مجموعه‌های Pages/Favorites/Tags/Saved searches را پنهان می‌کند؛ هاور/focus/click لوگو نمایش کامل موقت می‌دهد و عرض محتوا را ثابت نگه می‌دارد. انتخاب‌های اصلی حالت فعال و نام قابل دسترس دارند. پیش‌نمایش کوچک Settings نیز با پنهان‌سازی مجموعه‌ها هماهنگ شده است. همهٔ این تغییرات تازه و تست‌نشده‌اند؛ کاربر ابتدا بررسی می‌کند، سپس commit/push انجام می‌شود.

## مرحلهٔ بعد

پوستهٔ اصلی پیاده‌سازی اولیه شده و منتظر بررسی کاربر است. ایرادهای آن را ابتدا رفع کنید. قرارداد آن: لوگو در بالا، سایدبار و حالت‌های آن، جست‌وجو، New page با تمام عملیات فعلی و نوار محتوای صفحه. ابتدا رفتار فعلی هرکدام را از کد استخراج کنید تا چیزی از دست نرود. پس از تأیید این بخش، Home مرحلهٔ بعد است. بدهی‌های شورتکات، مدیریت focus و حرکت در این مسیر ثبت و به‌تدریج تکمیل شوند؛ برای ظاهر تازه منطق ذخیره‌سازی بازنویسی نشود.

## متن آماده برای چت جدید

اولین اجرا (۲۰۲۶-۱۱-۰۳): `VaultPicker` اکنون فقط اتصال سرویس‌های دسکتاپ به `src/onboarding/Onboarding.tsx` است. کاربر جدید سه قدم دارد: خوش‌آمد و زبان، نام و رنگ تأکیدی با پیش‌نمایش زندهٔ `WorkspaceHeader`، و انتخاب پوشه؛ در پایان پیش‌نمایش بزرگ می‌شود و فضای کاری باز می‌شود. کاربر دارای فضای کاری فهرست را با منوی راست‌کلیک می‌بیند و برای ساخت جدید دو قدم دارد. همهٔ قابلیت‌های قبلی (ساخت، باز کردن پوشهٔ موجود، Open، پیدا کردن پوشه، حذف از فهرست، خطاها) حفظ شده‌اند. در رابط «فضای کاری» جای Vault آمده است. کامپوننت جدید `Steps` و `AccentSwatches` مشترک با Settings اضافه شده‌اند (علامت ✓ و + متنی Settings به آیکون تبدیل شد). سبک‌های قدیمی `vault-list` و `acct-lang` حذف شدند؛ `.overlay.picker` به‌خاطر UpdateUI مانده است. پیش‌نمایش: `/onboarding-preview.html` روی سرور `npm run dev`. فضای کاری تازه دیگر صفحهٔ نمونهٔ «خوش آمدید» (`WELCOME_DOC`) نمی‌سازد و خالی شروع می‌شود؛ Home در اولین ورود برگهٔ «اولین یادداشت شما» را با مکان‌نمای آماده نشان می‌دهد. برای آزمودن اولین اجرا بدون دست زدن به فهرست فضاهای کاری اصلی، برنامه را با `NEVIS_APP_DATA` روی یک پوشهٔ جدا اجرا کنید. پس از ساخت فضای کاری در فلوی شروع، سناریوی اولین یادداشت (`src/onboarding/FirstNote.tsx`، اتصال در `FirstNoteStart.tsx` و `main.tsx`) پیش از برنامه نمایش داده می‌شود: برگه‌ای شبیه صفحهٔ واقعی (تاریخ و وضعیت ذخیره در بالا، عنوان بزرگ، متن ۱۷ پیکسلی، پیشنهادهای شروع در پایین برگه؛ `HomeNote` با حالت `bare`)، نکته‌های یکی‌یکی بدون تکرار پیام ذخیره، و در پایان برنامهٔ واقعی پشت برگه باز می‌شود، صفحه را باز می‌کند و برگه با FLIP به ردیف همان صفحه در سایدبار می‌رود. برای پنهان‌کردن درز بارگذاری مجدد، آخرین فریم فلوی شروع (`LandingFrame`) پیش از بارگذاری فضای کاری و هنگام ورود برگه دوباره کشیده می‌شود. پیش از اجرای JavaScript هنوز ممکن است صفحهٔ خالی کوتاهی دیده شود. نشانهٔ آن `nevis.firstNote` در localStorage است و اگر فضای کاری صفحه داشته باشد پاک می‌شود. پیش‌نمایش: `/onboarding-preview.html?scene=first-note`. تست نشده است. تست، build و typecheck اجرا نشده است.

اصلاح بصری بعدی Home: منظرهٔ زمان روز با import و فراخوانی واقعی `landscapeFor` دوباره به سربرگ برگشت؛ رنگ متن از روشن/تاریک بودن همان منظره پیروی می‌کند. Continue به ردیف مستقلی بالای Recent/تقویم تبدیل شده و Favorites در همان ردیف است. Recent و تقویم تک‌ماهه در یک ردیف مشترک با ارتفاع کشسان قرار گرفته‌اند تا لبهٔ پایینشان هم‌تراز باشد؛ کارت‌های اخیر در دسکتاپ از کاور thumbnail و قاب گروهی استفاده می‌کنند. همچنان تست/build/مرورگر اجرا نشده است.

آخرین اصلاح Home: در دسکتاپ با عرض حداقل ۱۱۰۰ و ارتفاع حداقل ۷۰۰، چیدمان بر اساس ارتفاع فضای محتوای یک ویوپورت تقسیم می‌شود؛ شش کارت اخیر جمع‌وجورند و پنجره‌های کوتاه‌تر کاور thumbnail دارند. تقویم فقط ماه فعلی را نشان می‌دهد و اندازهٔ خانه‌ها با ارتفاع موجود تنظیم می‌شود. در پنجره‌های کوچک‌تر اسکرول طبیعی برای جلوگیری از بریدن محتوا حفظ شده است. این اصلاح نیز هنوز تست نشده است.

Home نیز در پروژهٔ اصلی بازطراحی شد (`src/Home.tsx` و `design-system/home.css`): سربرگ آرام، چهار دسترسی سریع واقعی، Today جدید با نوار پیشرفت و سه کار باز از همهٔ صفحه‌ها و لینک مبدأ، شمار واقعی کارت‌های آمادهٔ مرور، ادامهٔ آخرین صفحه، شش صفحهٔ اخیر با کاور واقعی و تگ، تقویم فعالیت و علاقه‌مندی‌ها. نمودار حلقه‌ای قدیمی و بنر تزئینی Home حذف شده‌اند؛ استایل Home به‌صورت مستقیم جایگزین شده، نه با پوستهٔ دوم. کاور از `PageCoverPreview` در `Cover.tsx` و همان حل‌کنندهٔ attachment موجود استفاده می‌کند. ترجمه‌های جدید در `fa-home.ts` هستند. این مرحله هنوز توسط کاربر تست نشده؛ تست/build/مرورگر اجرا نشده و commit/push همچنان بعد از بررسی کاربر است. متن قدیمی برنامهٔ مرحلهٔ بعد در این سند تاریخی است: اکنون ابتدا Home و مراحل قبلی توسط کاربر بررسی شوند، سپس قاب صفحه و کاور/آیکون و ابزارهای صفحه مرحلهٔ بعد هستند.

رفتار نهایی لوگو در Icons only: هاور بازشدن موقت است؛ کلیک (یا فعال‌سازی با کیبورد) بازشدن را نگه می‌دارد، حتی پس از خروج نشانگر. کلیک بیرون سایدبار حالت نگه‌داشته‌شده را جمع می‌کند. این حالت موقتِ نشست است و ترجیح sidebar ذخیره‌شده را تغییر نمی‌دهد. این اصلاح نیز تست نشده است.

به‌روزرسانی همین نشست: سرچ عمومی صفحه‌ها و فرمان‌ها نیز به `CommandDialog` و `CommandResult` مشترک در design-system منتقل شد. ظاهر تخت، تب‌های All/Pages/Commands، گروه‌های نتایج، snippet و زمان ویرایش، ذخیرهٔ سرچ، پاک‌کردن، حالت‌های انتظار/خطا/بدون نتیجه و راهنمای کلیدها در سطح جدید قرار دارند. منطق جست‌وجو در `ui.tsx` مانده و سبک مرجع `design-system/commands.css` است؛ قواعد قدیمی palette از `areas/palette.css` حذف شدند. این تغییر نیز بدون اجرای تست، build یا مرورگر انجام شده و منتظر بررسی کاربر است.

صفحه (۲۰۲۶-۱۱-۰۳): سربرگ و ویژگی‌های `PageView` به اجزای design-system منتقل شد: آیکون (با کاور: کاشی روی لبهٔ پایین کاور که با هاور کمی بالا می‌آید و لبهٔ اکسنت می‌گیرد؛ بدون کاور: در ابتدای خط عنوان و هم‌جهت با آن) با منوی راست‌کلیک (تغییر/حذف)، دکمه‌های ghost افزودن آیکون و کاور که با هاور یا focus ظاهر می‌شوند، عنوان، و ویژگی‌ها به‌صورت ردیف‌هایی به سبک Settings (ستون برچسب با آیکون، ستون مقدار، خط نازک میان ردیف‌ها): وضعیت با Menu و رنگ؛ برچسب‌ها همه دیده می‌شوند و رنگی و خوانا هستند، کلیک روی نام برچسب صفحه‌های همان برچسب را در سایدبار باز می‌کند (رویداد `PICK_TAG`) و دکمهٔ حذف با هاور یا focus ظاهر می‌شود؛ و آخرین ویرایش. علاقه‌مندی عمل صفحه است نه ویژگی: ستارهٔ خطی در نوار بالای صفحه کنار Share که هنگام فعال بودن رنگ اکسنت می‌گیرد. کاور داخل ستون صفحه و هم‌عرض متن است، با دکمه‌های design-system و منوی راست‌کلیک. نوار قالب‌بندی جایش را نگه می‌دارد اما فقط هنگام نوشتن یا هاور دیده می‌شود. قالب‌های شروع سریع در یک خط و قابل اسکرول‌اند. منوی راست‌کلیک متن از `useMenu` می‌آید (Popover و MenuItem قدیمی حذف شد) و قالب‌بندی زیرمنو دارد. Backlinks با `Row` و شمارندهٔ `ds-badge`. سبک‌ها با کلاس‌های `pg-` فقط در `areas/page.css` هستند و قواعد قدیمی page-meta، page-top، page-tools، templates، findbar و backlinks از page.css، page-meta.css، bubbles.css، panels.css، palette.css، print.css، shell.css، scrollbars.css و screens.css حذف شدند. ظاهر داخلی نوار ابزار ویرایشگر، پیکر کاور، outline پنل و Reader هنوز مرحلهٔ بعدند. typecheck گذشت و در مرورگر (فارسی و انگلیسی، روشن/تاریک، عرض باریک) بررسی شد؛ صفحه با Backlinks دیده نشده است.

بازطراحی دوم صفحه (۲۰۲۶-۱۱-۰۳): اجزای مشترک تازه در design-system: `ChipButton` (`ds-chip-btn`)، `Tag` (`ds-tag`)، `PropertyList`/`PropertyRow` (`ds-props`)، `ds-chip-field`، `ds-icon-btn--toggle`، `ds-swatches`/`ds-swatch`، `ds-color` و `IconPicker`. چیپ‌ها و برچسب‌ها از تنظیم گردی گوشه (`--ds-r-sm`) پیروی می‌کنند. انتخاب کاور از پس‌زمینه‌های design-system در پنج گروه است (کاورهای قدیمی همچنان نمایش داده می‌شوند). مجموعهٔ آیکون design-system به ۲۱۴ آیکون رسید (گروه Subjects and objects) و انتخاب آیکون صفحه از همین مجموعه است، با رنگ دلخواه. Reader mode بازطراحی شد: صفحه روی پس‌زمینهٔ ساده، خط پیشرفت نازک و یک نوار ابزار از اجزای design-system؛ همهٔ قواعدش در `areas/reader.css`. علاقه‌مندی ستارهٔ خطی در نوار بالای صفحه است. منوهای دارای زیرمنو دیگر دکمه داخل دکمه نیستند و زیرمنو نسبت به پنجره جا می‌گیرد. اسکرول افقی درخت صفحه‌ها در حالت Icons only هنگام باز شدن موقت برمی‌گردد و ریل آن بدون انتظار برای frame اندازه‌گیری می‌شود.
نوار قالب‌بندی بازطراحی شد (`Toolbar.tsx`، `areas/toolbar.css`؛ قواعد قدیمی از editor.css، panels.css، screens.css و surfaces.css حذف شد): دکمه‌های `ds-icon-btn`، منوهای design-system، تراز در یک منو، و در عرض کم بقیه در More. همهٔ دکمه‌ها میانبر دارند و در tooltip دیده می‌شود؛ میانبرهای تازه: Heading 1–3 (Ctrl+Alt+1..3)، Link (Ctrl+Shift+K)، Link to page (Ctrl+Alt+K)، Insert image (Ctrl+Alt+I)، Insert table (Ctrl+Alt+T)، تراز چپ/وسط/راست (Ctrl+Shift+L/E/R). همه با کلید فیزیکی کار می‌کنند و به زبان کیبورد وابسته نیستند. میانبر سایدبار Alt+1 شد.
کشیدن و رها کردن بلوک‌ها و ستون‌ها (۲۰۲۶-۱۱-۰۳): منوی کوچکی که وسط کشیدن زیر نشانگر باز می‌شد (tray با مینیاتورها) حذف شد؛ خود صفحه انتخاب‌گر است. سه نتیجه: بالا/پایین (حتی مستقیم در حاشیه کنار grip) فقط جابه‌جایی با خط اکسنت؛ رفتن روی بخش چپ/راست خود بلوک (حدود یک‌پنجم عرض، ۴۸ تا ۱۵۰ پیکسل) پیش‌نمایش ستون‌ها؛ لبه یا فاصلهٔ یک چیدمان ستون تازه (حداکثر ۳). ستون فقط پس از حداقل ۳۲ پیکسل حرکت افقی ساخته می‌شود تا کشیدن عمودی هرگز تصادفی ستون نسازد؛ قبلاً ناحیهٔ ستون‌سازی روی همان حاشیه‌ای بود که grip در آن است. حاشیهٔ کنار چیدمان، نیمهٔ بالا/پایین، بلوک را بالای/پایین چیدمان می‌برد. رها کردن روی جای فعلی بلوک دیگر «خطا» نیست و به گزینهٔ واقعی زیرش می‌رسد. نشانگر کشیدن (`ds-drag-ghost`) دو خط دارد: چه چیزی جابه‌جا می‌شود و رها کردن چه می‌کند (آماده/بی‌اثر/غیرمجاز با علت). مبدأ با `ds-drag-source` کم‌رنگ می‌شود و پیش‌نمایش `ds-snap-preview` با `ds-snap-col` است؛ همه در `components.css` و راهنما. منوی grip و Ctrl+Alt+M به `Menu` مشترک منتقل شد (prop تازهٔ `autoFocus`)، با آیکون و میانبر، و فقط جابه‌جایی‌های ممکن را نشان می‌دهد. مدل برنامه‌ریزی (`snapModel.ts`) دست نخورده است. فایل‌ها: `editor/dragHandle.ts`، `editor/snapTargets.ts`، `LayoutControls.tsx`، `design-system/Menu.tsx`، `components.css`، `areas/layout.css`، `fa.ts`. typecheck و check:ui گذشت؛ تست و مرورگر اجرا نشده و منتظر بررسی کاربر است. راهنما اکنون حداکثر ۳ ستون و میانبرهای Ctrl+Alt (نه Alt+Shift) را درست ذکر می‌کند.

پنل کناری صفحه (`PagePanel`) بازطراحی شد: سربرگ با آیکون و نام صفحه، `Facts` (تعداد کلمه، زمان مطالعه، زیرصفحه‌ها، آخرین ویرایش)، شبکهٔ عمل‌ها با جزء تازهٔ `ActionGrid`/`ActionTile` (زیرصفحه، کاور، تاریخچه، حالت مطالعه، Markdown، چاپ)، فهرست عنوان‌ها و ناوبری با دکمهٔ + برای زیرصفحه. جست‌وجو، علاقه‌مندی، فلش‌کارت، جدول صفحه‌ها و تنظیمات از پنل برداشته شدند چون در نوار بالا و سایدبار هستند. نوار حالت مطالعه هم مثل نوار قالب‌بندی شد و عرض صفحه به‌جای اسلایدر منو است.
