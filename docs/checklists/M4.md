# چک‌لیست مالک: M4 (ورود و نشست)

پیش‌نیاز: HTTPS برای iPhone (`docs/dev-https.md`) — کوکی `Secure` روی HTTP ساده در Safari ذخیره نمی‌شود.

اجرا (یک سرور که هم API و هم وب را می‌دهد):
```bash
server/scripts/demo.sh        # http://localhost:8788
```
برای گوشی روی HTTPS: `NEVIS_TLS_CERT/KEY` با `pnpm --filter web dev` طبق `docs/dev-https.md` (سرور Go جدا روی ۸۷۸۷ با `DEV_MODE=1 REGISTRATION=open POW_BITS=8`).

| # | کار | انتظار | نتیجه (✓/✗ + توضیح) |
|---|---|---|---|
| 1 | Safari macOS: «حساب ندارم» → نام و گذرواژه → ساخت حساب | کلید بازیابی نمایش داده می‌شود؛ «فضای کار تازه» ساخته می‌شود | |
| 2 | همان‌جا صفحه را reload کنید و تب را ببندید و دوباره باز کنید | هنوز وارد هستید (فهرست فضاهای کار) | |
| 3 | iPhone Safari (HTTPS): ورود با همان حساب | ورود موفق و فضای کار دیده می‌شود | |
| 4 | iPhone: Safari را کامل ببندید (swipe up) و دوباره باز کنید | هنوز وارد هستید | |
| 5 | در Mac «خروج» بزنید | iPhone **هنوز وارد** است (reload کنید) | |
| 6 | گذرواژهٔ غلط بزنید | پیام فارسی «نام کاربری یا گذرواژه درست نیست»؛ بعد از چند بار پیام «تلاش بیش از حد» | |
| 7 | ۲۴ ساعت بعد دوباره باز کنید | هنوز وارد (نشست ۹۰ روزه، لغزان) | |

اگر ۲ یا ۴ شکست خورد: بنویسید کدام مرورگر و آیا حالت Private/ITP یا «Prevent cross-site tracking» روشن بود.
