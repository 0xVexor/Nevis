# ADR-0008: سریال‌سازی و قالب فایل‌ها (پاسخ به «JSON بماند یا عوض شود؟»)

- وضعیت: **تصمیم‌شده**
- اطمینان: ۸۵٪
- تاریخ: 2026-11-20
- مرتبط: ADR-0002، ADR-0003، ADR-0005، ADR-0009، ADR-0011؛ تحقیق: R7 (همه)، R6 §2 و §5

## سؤال مالک
«فرمت فایل/داده‌ی ما JSON است؛ باید عوض شود یا از استاندارد خاصی پیروی کند؟»

## پاسخ کوتاه
JSON می‌ماند، با یک قاعدهٔ سخت‌گیرانهٔ مشخص (زیرمجموعهٔ I-JSON، RFC 7493 / RFC 8259). **دو چیز JSON نیستند و نباید باشند:** بدنهٔ سند (Yjs دودویی) و بایت پیوست‌ها. **کانونیک‌سازی (JCS) لازم نیست**، چون در v1 هیچ JSONی هش یا امضا نمی‌شود. JSON ProseMirror دیگر «حالت ذخیره‌شده» نیست؛ projection و قالب export است.

## قواعد JSON (در همهٔ JSONهای ما؛ parser و serializer یکی در هر زبان)
1. **UTF-8 بدون BOM** (RFC 8259 §8.1).
2. **کلید تکراری = خطا** در parse (نه «آخری برنده»). در TS یک parser سخت‌گیر برای ورودی شبکه و import (`packages/protocol/json.ts`)؛ در Go decoder با بررسی تکرار.
3. **عدد:** فقط **عدد صحیح** در بازهٔ ±(2^53−1). **هیچ float** در قالب‌های ما. عدد اعشاری کاربر = رشتهٔ اعشاری (ADR-0004). `NaN`/`Infinity`/`-0` ممنوع.
4. **شناسه‌ها، HLC، زمان‌ها همیشه رشته** (UUIDv7، HLC، ISO 8601 UTC با `Z`). استثنا: `seq`، `rt`، اندازه‌ها، `sv`، `v`، `kid` که عدد صحیح کوچک‌اند.
5. **`null`:** در envelope و attribute ProseMirror ممنوع؛ فقط در مقدار فیلد رکورد به معنای «خالی‌شده» (ADR-0004). فیلد اختیاری = حذف کلید، نه `null`.
6. **رشته‌ها:** surrogate تنها ممنوع (خطای parse). ترتیب کلید معنا ندارد و نباید به آن تکیه شود.
7. **یونیکد (حل تعارض R5 و R7):** متن بدنه در Yjs **هرگز بازنویسی نمی‌شود** (نه NFC، نه حذف ZWNJ)، چون نرمال‌سازی با IME و موقعیت‌های Yjs درگیر می‌شود. NFC فقط روی (الف) کلیدها و برچسب‌ها (نام تگ، نام گزینهٔ select، نام property) در لحظهٔ ذخیره، و (ب) خط لولهٔ جست‌وجو. متن paste‌شده هم دست نمی‌خورد. ZWNJ (U+200C) **همیشه** حفظ می‌شود.
8. **سریال‌کننده:** `JSON.stringify` بدون فاصله برای سیم؛ با تورفتگی ۲ فاصله فقط برای فایل‌های export که انسان می‌خواند. Go: `encoding/json` با `SetEscapeHTML(false)`.
9. **شکل ProseMirror JSON:** همان `node.toJSON()` با schema نسخهٔ `sv`، همهٔ attrها با مقدار (پیش‌فرض پرشده). ریشه همیشه `{"type":"doc","content":[…]}`.

## کانونیک‌سازی
- **v1: لازم نیست.** idempotency با مقایسهٔ SHA-256 **بایت‌های واقعی** envelope است که کلاینت در outbox نگه داشته و دوباره همان را می‌فرستد. هش پیوست روی بایت خام است. checksum باندل روی بایت فایل است.
- **AAD رمزنگاری آینده** از JSON ساخته نمی‌شود؛ الحاق ثابت سربرگ‌هاست (ADR-0011)، پس JCS برای E2EE هم لازم نیست.
- اگر روزی امضای JSON لازم شد: **RFC 8785 (JCS)**، نه قالب خودساخته (`canonical()` قدیمی با `to_vec_pretty` کانونیک نبود؛ R7 بند ۵).

| JSON ProseMirror به‌عنوان حالت ذخیره‌شده | ادغام هم‌زمان ندارد (ADR-0003). |
| Portable Text برای export | سود کم؛ schema ما ProseMirror است (R7 §5). |

## پیامدها
- یک parser سخت‌گیر در TS و یک بررسی در Go با بردارهای آزمون مشترک (`packages/protocol/vectors/json-*.json`: کلید تکراری، عدد بزرگ، float، surrogate تنها، BOM، `-0`).
- هیچ‌کس نباید فرض کند ترتیب کلید یا فاصله پایدار است.

## چه چیزی تصمیم را برمی‌گرداند
- نیاز به امضای محتوا (مثلاً اشتراک عمومی امضاشده) → افزودن JCS فقط برای همان قالب.
- اندازه‌گیری حجم/زمان pull اولیه در M13 (بالا).
