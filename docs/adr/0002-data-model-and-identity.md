# ADR-0002: مدل داده و هویت

- وضعیت: **تصمیم‌شده**
- اطمینان: ۸۵٪
- تاریخ: 2026-11-20
- مرتبط: ADR-0003، ADR-0004، ADR-0005، ADR-0008؛ تحقیق: R4 §3، R6 §6، R7 §2، `storage-and-sync-options.md` §F و §3

## زمینه
هر چیزی که بعد از اولین داده‌ی واقعی تغییرش گران است باید الان قطعی شود: شکل شناسه‌ها، ساعت منطقی، نسخه‌ها و حذف.

## موجودیت‌ها (entity)
هر موجودیت یک `id` دارد و از دو بخش ساخته می‌شود: **فیلدها** (رجیستر LWW، ADR-0004) و در صورت نیاز **بدنه** (یک `Y.Doc`، ADR-0003). شناسهٔ بدنه همان شناسهٔ موجودیت است.

| `kind` | فیلدهای اصلی | بدنه Yjs | یادداشت |
|---|---|---|---|
| `page` | `title`، `parent`، `sortKey`، `icon`، `cover`، `tag:<tagId>`، `trashed` | دارد | پوشه = صفحه با فرزند |
| `database` | `title`، `parent`، `sortKey`، `trashed` | دارد (توضیح) | |
| `property` | `db`، `name`، `type`، `config`، `opt:<optionId>`، `sortKey`، `trashed` | ندارد | |
| `view` | `db`، `name`، `type`، `config`، `sortKey`، `trashed` | ندارد | `config` کل‌مقدار |
| `row` | `db`، `sortKey`، `trashed`، `c:<propId>`، `c:<propId>/<elemId>` | دارد | ردیف همان صفحه است |
| `card` | `deck`، `source`، `suspended`، `trashed` | ندارد | مرور = event |
| `tag` | `name`، `color` | ندارد | |
| `savedSearch` | `name`، `query`، `sortKey`، `trashed` | ندارد | |
| `settings` | تنظیمات همگام workspace | ندارد | id ثابت = `workspaceId` |

- `kind` و `createdAt` در اولین op موجودیت نوشته می‌شوند و تغییرناپذیرند.
- **تسک‌ها موجودیت نیستند:** هر `taskItem` در بدنهٔ صفحه یک تسک است و فهرست تسک‌ها مشتق است (همان رفتار `taskData.ts` قدیمی).
- **رویدادها** (`event`): `review` (مرور فلش‌کارت) و `version` (نسخهٔ تاریخچهٔ صفحه). شناسه دارند و هرگز ویرایش نمی‌شوند.
- **تنظیمات per-device** (اندازهٔ پنجره، تم این دستگاه) فقط در `meta` محلی؛ هرگز سینک نمی‌شوند.

## شناسه‌ها
- **همهٔ شناسه‌های ساخته‌شده در کلاینت = UUIDv7** (RFC 9562)، رشتهٔ کوچک ۳۶ کاراکتری با خط تیره: workspace، موجودیت، op، event، دستگاه، `blockId`، option، tag.
  - دلیل: مرتب‌پذیری زمانی برای ایندکس و دیباگ؛ ۷۴ بیت تصادفی کافی برای یکتایی بدون هماهنگی؛ کتابخانه و پشتیبانی در هر سه زبان.
  - هزینه: زمان ساخت را لو می‌دهد (R6 §6). سرور به‌هرحال زمان دریافت را می‌بیند؛ پذیرفته شد.
  - nanoid رد شد: مرتب‌پذیر نیست. ULID رد شد: استاندارد RFC ندارد و قالب متفاوت.
  - مولد یکنواخت در هر process (روش RFC 9562 §6.2 با شمارنده در `rand_a`).
- **شناسه‌ها همیشه رشته‌اند، هرگز عدد.** شناسهٔ حساب کاربری را سرور می‌سازد (UUIDv7).
- **deviceId:** یک بار در اولین اجرا ساخته و در `meta` نگه داشته می‌شود؛ هر نصب/پروفایل مرورگر یک دستگاه است. پاک شدن دادهٔ محلی = دستگاه جدید.
- **Yjs `clientID`** به یک نمونهٔ `Y.Doc` تعلق دارد؛ هرگز ذخیره، دوباره‌استفاده یا بین تب‌ها مشترک نمی‌شود (پیش‌فرض Yjs: ۳۲ بیت تصادفی برای هر نمونه).

## HLC (ساعت منطقی ترکیبی)
- قالب رشته‌ای با طول ثابت تا مقایسهٔ لغت‌نامه‌ای = ترتیب کامل:
  `"<ms: 12 hex>-<counter: 4 hex>-<deviceId>"` مثال: `"019a8f3c2b10-0000-019a8f3c-2b10-7c3e-8f00-1a2b3c4d5e6f"`.
  - `ms` = ۴۸ بیت میلی‌ثانیهٔ یونیکس (هم‌اندازهٔ UUIDv7)؛ `counter` = ۱۶ بیت؛ `deviceId` کامل برای شکستن تساوی (کوتاه کردنش ممنوع).
- الگوریتم (Kulkarni و همکاران ۲۰۱۴؛ PDF در تحقیق خوانده نشد، R4 §3 — الگوریتم استاندارد است و با آزمون خاصیت پوشش داده می‌شود):
  - ارسال/رویداد محلی: `l' = max(l, now)`؛ اگر `l' == l` آنگاه `c = c+1` وگرنه `c = 0`.
  - دریافت با `(lm, cm)`: `l' = max(l, lm, now)`؛ `c` طبق قاعدهٔ استاندارد.
  - سرریز `c` (> 0xffff): `l = l+1`، `c = 0`.
  - آخرین HLC در هر تراکنش نوشتن در `meta.hlc` ذخیره می‌شود؛ بعد از restart هرگز عقب نمی‌رود.
- **حد انحراف ساعت:** سرور opی را که بخش `ms` آن بیش از **۱۰ دقیقه** جلوتر از ساعت سرور باشد رد می‌کند (`422 clock_ahead`، ADR-0005). کلاینت پیام «ساعت دستگاه شما جلو است» نشان می‌دهد و ارسال را متوقف می‌کند، بدون از دست دادن داده.

## نسخه‌ها (هر کدام مستقل)
| نام | کجا | معنا | قاعده |
|---|---|---|---|
| `v` | envelope | قالب envelope | اکنون `1` |
| `sv` | envelope و `doc_state.max_sv` | نسخهٔ schema داده (ProseMirror + رکوردها) | عدد صحیح از `1`؛ کلاینت op با `sv` بزرگ‌تر از نسخهٔ خودش را **اعمال نمی‌کند** و در inbox نگه می‌دارد؛ سندی که `max_sv` آن بیشتر است در ادیتور باز نمی‌شود (پیام «به‌روزرسانی لازم») |
| `proto` | سربرگ HTTP `Nevis-Proto` | قرارداد HTTP | سرور `426` با `minProto` |
| `minSv` | سرور، per workspace | جلوگیری از نوشتن کلاینت قدیمی بعد از تغییر ناسازگار | فقط بالا می‌رود |
| `storeVersion` | `meta` محلی | قالب پایگاه محلی | ADR-0001 بند ۹ |
| `formatVersion` | `manifest.json` باندل | قالب export | ADR-0009 |
| `normVersion` | ایندکس جست‌وجو | قواعد نرمال‌سازی | تغییر = بازسازی ایندکس |

- تغییر schema در داخل یک `sv` ممنوع است. هر تغییر = `sv+1` و یک آزمون fixture.
- تغییر افزایشی (نوع گره یا فیلد جدید) فقط `sv` را بالا می‌برد. تغییر ناسازگار علاوه بر آن `minSv` سرور را بالا می‌برد.

## حذف و tombstone
- **سطل زباله:** فیلد `trashed` (boolean، LWW). بازگرداندن = `trashed=false` با HLC جدیدتر. «نبودن» هرگز به معنای «حذف» نیست.
- **حذف دائمی (purge):** درخواست صریح به سرور برای یک موجودیت؛ سرور همهٔ opهای آن `doc` را حذف می‌کند، شناسه را در جدول `purged` نگه می‌دارد و opهای بعدی برای آن را با وضعیت `purged` رد می‌کند تا دستگاه آفلاین آن را زنده نکند. یک op نشانگر `purge` منتشر می‌شود تا دستگاه‌ها دادهٔ محلی را پاک کنند. پیاده‌سازی: M13.
- رجیسترهای `trashed` و جدول `purged` هرگز GC نمی‌شوند (کوچک‌اند).
- عناصر مجموعه (`c:<propId>/<elemId>`) با مقدار `false` حذف می‌شوند و tombstone می‌مانند.

## پیامدها
- همهٔ کد باید `id` و HLC را رشته بداند؛ هیچ عدد بزرگی در JSON نیست (ADR-0008).
- HLC هر فیلد ~۵۴ بایت است؛ برای ۱۰k صفحه با ۱۰ فیلد کمتر از ۶MB. پذیرفته شد.

## چه چیزی تصمیم را برمی‌گرداند
- اگر در E2EE نشت زمان ساخت شناسه پذیرفتنی نباشد: برای `doc` در envelope یک شناسهٔ تصادفی مستقل (UUIDv4) لازم می‌شود. چون envelope از روز اول `doc` جدا دارد، این تغییر فقط در لایهٔ رمزنگاری است.
- آزمون خاصیت HLC در M2: یکنواختی بعد از restart، ترتیب کامل، سرریز counter، دریافت از آینده تا حد ۱۰ دقیقه.

## یادداشت اجرایی (2026-11-21، M8a؛ **نیازمند تأیید معمار**)
بند «هر تغییر schema = `sv+1`» در عمل برای هر **milestone** یک بار اعمال می‌شود، نه برای هر گروه بلوک: `SV` در شروع کار schema آن milestone بالا می‌رود و تا برچسب milestone ثابت می‌ماند؛ تغییرات میانی فقط افزایشی‌اند (گرهٔ تازه، attribute تازه با پیش‌فرض غیر null) و با fixtureهای طلایی (مقایسه با حذف مقدارهای پیش‌فرض) بررسی می‌شوند؛ commitهای میانی منتشر نمی‌شوند. جزئیات و دلیل: `docs/formats/golden-fixtures.md`. اگر معمار هر گروه را یک `SV` جدا بخواهد، `SV` فقط یک ثابت است (`packages/protocol/src/version.ts`) و تغییر آن یک‌خطی است.

**یادداشت M9:** `SV = 3` (صفت‌های `blob`/`mime`/`size` برای `image`، گرهٔ `file`، `drawing.sceneBlob`)، یک bump برای کل milestone طبق همین سیاست؛ منتظر تأیید معمار. جزئیات: `docs/reports/12-m9-attachments.md`.
