# ADR-0001 — انتخاب Editor

- وضعیت: **پذیرفته‌شده** (2026-10-24؛ تست IME واقعی با کیبورد کاربر هنوز باز است)
- تاریخ: 2026-10-24

## زمینه
هسته محصول، ادیتور با رفتار bidi مثل Word است (docs/01-problem-and-mvp.md). دو کاندید با یک سناریوی تست یکسان مقایسه شدند: TipTap v3.32 (`spike/tiptap`، روی C:) و BlockNote v0.56 (`F:\pro\not\spike\blocknote`).

## نتایج مقایسه (اندازه‌گیری در مرورگر)

| معیار | TipTap | BlockNote |
|---|---|---|
| جهت خودکار هر پاراگراف | ✅ با `dir=auto`/plaintext | ❌ پیش‌فرض همه LTR؛ با CSS قابل‌اصلاح |
| جهت دستی هر بلاک (RTL/LTR) | ✅ attribute `dir` روی node | ❌ در schema وجود ندارد (فقط `textAlignment`) |
| لیست با آیتم فارسی/انگلیسی مخلوط | ✅ bullet کنار متن | ❌ با CSS متن راست می‌شود ولی bullet (`::before` در flex) سمت چپ می‌ماند |
| جدول RTL (ترتیب ستون‌ها) | ✅ `dir` روی table و cell | ❌ props جدول فقط `textColor`؛ `dir="rtl"` ورودی نادیده گرفته شد |
| Code block همیشه LTR + highlight | ✅ | ✅ (LTR؛ highlight تست نشد) |
| Paste: heading، bold، لیست، کد، جدول چت AI | ✅ | ✅ |
| Paste جدول Word (`MsoTableGrid`) | ✅ و `dir=rtl` سلول حفظ شد | ✅ ساختار 2×2؛ جهت از دست می‌رود |
| UI آماده (slash menu، drag handle، toolbar) | ❌ باید ساخته شود | ✅ آماده |
| سرعت شروع | کندتر | سریع‌تر |

تست‌نشده در هر دو: تایپ واقعی فارسی با IME، caret در متن ترکیبی، صفحه بزرگ، LaTeX.

## تصمیم (پیشنهاد)
**TipTap (ProseMirror) را انتخاب کنیم.**

## دلیل
- نیاز اصلی ما (جهت هر بلاک، جدول RTL، لیست درست) در BlockNote در مدل داده وجود ندارد. اضافه کردن آن یعنی نوشتن custom schema برای تقریباً همه بلاک‌ها، که مزیت «آماده بودن» را از بین می‌برد.
- در TipTap همین‌ها با حدود ۱۰۰ خط extension حل شد.

## هزینه‌ها و ریسک‌ها
- باید slash menu، drag handle، block menu و floating toolbar را خودمان بسازیم (تقریباً کل UI ادیتور). این بزرگ‌ترین هزینه است.
- دو دور زدن لازم بود: `dir=auto` روی `<p>` داخل `<li>/<td>` نباید باشد؛ NodeView جدول resizable باید با `View` سفارشی `dir` را بنویسد. این‌ها به نسخه TipTap وابسته‌اند و باید تست regression داشته باشند.
- جایگزین: BlockNote + custom schema. فقط اگر سرعت UI مهم‌تر از کنترل bidi شد.

## نتایج تست‌های تکمیلی (TipTap، 2026-10-24، مرورگر خودکار)

**تایپ** (کاراکتر به کاراکتر، نه IME واقعی):
- متن ترکیبی فارسی/انگلیسی/ارقام ۱۲۳ و ۴۵۶: درست ثبت شد.
- نیم‌فاصله (ZWNJ) حفظ شد.
- جهت هر پاراگراف از اولین حرف قوی تعیین شد، حتی هنگام تایپ در پاراگراف خالی.
- `Ctrl+Shift+←` پاراگراف را RTL کرد و `Ctrl+Z` برگرداند.

**صفحه بزرگ** (Chrome، تایپ در وسط سند، شامل layout):

| بلاک‌ها | DOM | بارگذاری | تایپ p50 / p95 |
|---|---|---|---|
| ۵۰۰۰ (با جدول و کد) | ~۱۷٬۰۰۰ | ~۱٫۰ ثانیه | ۱۵ / ۱۹ ms |
| ۱۵٬۰۰۰ | ~۲۱٬۰۰۰ | ~۱٫۲ ثانیه | ۲۸ / ۳۴ ms |

Undo×۲۰ روی ۵۰۰۰ بلاک: ۶۲ ms.

نتیجه: تا حدود ۵۰۰۰ بلاک روان است؛ در ۱۵٬۰۰۰ بلاک تایپ محسوس کند می‌شود (>۲۰ms). صفحه‌های واقعی معمولاً خیلی کوچک‌ترند، ولی برای صفحات بزرگ باید بعداً راه‌حل داشته باشیم (تقسیم به زیرصفحه، یا virtualization).

## هنوز باز
- IME واقعی ویندوز/مک (کیبورد فارسی سیستم): فقط با تایپ دستی شما قابل تأیید است.
- caret/selection در مرز متن ترکیبی با ماوس و کیبورد.
- LaTeX، مرورگر Safari/WebKit (Tauri روی macOS از WKWebView استفاده می‌کند) و WebView2 در ویندوز (تست‌ها در Chrome بود).
