# ADR-0004: دادهٔ ساختاریافته و قواعد تعارض

- وضعیت: **تصمیم‌شده**
- اطمینان: ۸۰٪
- تاریخ: 2026-11-20
- مرتبط: ADR-0002، ADR-0003، ADR-0005؛ تحقیق: R4 §2-3، `storage-and-sync-options.md` §B-2 و §3-1

## زمینه
پایگاه‌داده (property، view، row، cell)، فلش‌کارت، تنظیمات، متادیتای صفحه و جست‌وجوی ذخیره‌شده Yjs لازم ندارند ولی باید بدون از دست رفتن دادهٔ هم‌زمان ادغام شوند. اپ قدیمی برای هر کدام merge جدا داشت (`db_merge.rs`، `kv_merge.rs`).

## گزینه‌ها
| گزینه | نتیجه |
|---|---|
| همه‌چیز در Yjs (Y.Map per entity) | رد: هزینهٔ بارگذاری Y.Doc برای هر ردیف؛ رشد tombstone؛ کوئری و ایندکس سخت. |
| LWW کل رکورد | رد: دو ویرایش هم‌زمان روی دو ستون یک ردیف همدیگر را پاک می‌کنند. |
| OR-set کامل (add-wins با tag) برای مجموعه‌ها | رد برای v1: نیاز به نگهداری tagهای حذف‌شده؛ برای کاربرد ما سود کم. |
| **رجیستر LWW سطح فیلد با HLC + مجموعه با رجیستر per عنصر + رویداد تغییرناپذیر** | **انتخاب.** یک primitive، همگرایی ساده و قابل آزمون. |

## تصمیم
### primitiveها
1. **رجیستر LWW:** کلید `(ent, f)`، مقدار JSON، و `hlc`. نوشتن فقط اگر `hlc` جدید از موجود بزرگ‌تر باشد (مقایسهٔ رشته). HLC برابر یعنی همان op (deviceId در HLC است)؛ بی‌اثر.
2. **مجموعه = رجیستر per عنصر:** کلید فیلد `<prefix>:<elemId>` یا `c:<propId>/<elemId>`، مقدار `true`/`false`. دو افزودن هم‌زمان عنصرهای متفاوت هر دو می‌مانند (مشکل اصلی LWW کل‌مقدار حل می‌شود). افزودن و حذف هم‌زمانِ **همان** عنصر: HLC بزرگ‌تر برنده است (نه add-wins). مستند و پذیرفته شد.
3. **رویداد تغییرناپذیر:** `event(id)`؛ درج اگر نیست؛ هرگز تغییر نمی‌کند؛ اجتماع.
4. **ترتیب:** فیلد `sortKey` = رشتهٔ fractional index (کتابخانهٔ `fractional-indexing`) **به‌علاوهٔ پسوند تصادفی ۴ کاراکتری** تا دو درج هم‌زمان در یک جا کلید برابر نسازند. مرتب‌سازی: `(sortKey, id)`.
5. **قاعدهٔ شکل رکورد:** فیلدها تخت‌اند. هر مجموعه‌ای که ممکن است هم‌زمان تغییر کند با فیلدهای کلیددار `prefix:<id>` بیان می‌شود، **هرگز آرایه**. آرایه و شیء فقط برای مقدارِ اتمیِ کل‌مقدار مجاز است (مثل `config` نما).
6. **`null` در مقدار فیلد** فقط یعنی «خالی شده» و یک نوشتن واقعی با HLC است. (این با قاعدهٔ «بدون null» در attributeهای ProseMirror و envelope فرق دارد؛ ADR-0008.)

### قواعد هر نوع داده
| داده | مدل | تعارض |
|---|---|---|
| متادیتای صفحه (`title`، `parent`، `icon`، `cover`، `sortKey`) | رجیستر | LWW per فیلد. عنوان کل‌رشته است: ویرایش هم‌زمان عنوان یکی را نگه می‌دارد. |
| تگ صفحه | مجموعه `tag:<tagId>` | per عنصر |
| جابه‌جایی صفحه در درخت | `parent` + `sortKey` | LWW. **چرخه:** اگر ادغام چرخه بسازد (A زیر B و B زیر A)، projection درخت، صفحه‌ای را که آخرین `parent` آن HLC بزرگ‌تری دارد به ریشه می‌برد (فقط در نما؛ داده عوض نمی‌شود). آزمون خاصیت لازم. |
| property پایگاه‌داده | رجیستر؛ گزینه‌های select با `opt:<optionId>` = `{"name","color","sortKey"}` یا `null` | دو گزینهٔ هم‌زمان هر دو می‌مانند |
| view | `config` کل‌مقدار JSON | LWW کل config (فیلتر و مرتب‌سازی همزمان: یکی برنده) |
| row | `c:<propId>` برای مقدار تکی؛ `c:<propId>/<elemId>` برای multi-select و relation | LWW per سلول؛ مجموعه per عنصر |
| سلول عددی | **رشتهٔ اعشاری** نرمال (ارقام ASCII، `-` و `.` اختیاری، بدون توان)، مثل `"12.50"` | ارقام فارسی در ورود تبدیل می‌شوند؛ عدد اعشاری هرگز JSON number نیست |
| سلول تاریخ | `"2026-11-20"` یا `"2026-11-20T08:30:00.000Z"` | نمایش شمسی فقط در UI |
| سلول متنی بلند | رشته؛ LWW | برای متن هم‌زمان باید از بدنهٔ ردیف (Yjs) استفاده شود |
| تسک | گرهٔ `taskItem` در بدنهٔ Yjs با attrهای `checked` و `due` (پیش‌فرض `""`) | Yjs؛ فهرست تسک‌ها مشتق |
| فلش‌کارت | `card` رجیستر؛ هر مرور = `event` با `{"card","rating","reviewedAt","durationMs"}` | زمان‌بندی (FSRS) = fold قطعی روی رویدادها به ترتیب `(hlc, id)`؛ مشتق و قابل بازسازی؛ دو مرور هم‌زمان در دو دستگاه هر دو حفظ می‌شوند |
| تنظیمات همگام | موجودیت `settings` با فیلد per تنظیم | LWW per فیلد |
| تنظیمات دستگاه | `meta` محلی | سینک نمی‌شود |
| جست‌وجوی ذخیره‌شده | رجیستر | LWW |
| نسخهٔ تاریخچه | `event` نوع `version` | اجتماع؛ حذف با purge |

### ارتباط با Yjs
ردیف پایگاه‌داده یک موجودیت با بدنه است (`rowId == bodyDocId`)؛ فیلدها و بدنه مستقل همگام می‌شوند.

## پیامدها
- یک موتور ادغام (`applyFieldOp`) برای همهٔ داده‌های غیرمتنی؛ تمام قواعد بالا «شکل داده» هستند نه کد جدا.
- مقدارهای JSON بزرگ (config نما) کل‌مقدار LWW هستند؛ ویرایش هم‌زمان دو فیلتر در یک نما یکی را از دست می‌دهد.

## چه چیزی تصمیم را برمی‌گرداند
- اگر در هم‌نویسی چندنفره «حذف هم‌زمان با افزودن» در multi-select مشکل واقعی شد: ارتقا به OR-set برای همان فیلد، بدون تغییر بقیه.
- آزمون: harness همگرایی M2 (رجیستر و مجموعه)، M7 (پایگاه‌داده کامل، چرخهٔ درخت، fold فلش‌کارت).
