# ADR-0014: عرض ذخیره‌شدهٔ ستون‌های جدول (SV 4)

تاریخ: 2026-11-22. وضعیت: پیاده‌سازی برای درخواست مالک جهت بازگرداندن ریسایز جدول نسخهٔ قبلی.

قرارداد قبلی `colwidth` را حذف کرده بود؛ در نتیجه ریسایز قابل ذخیره‌سازی نبود. هر سلول و سرستون اکنون `colwidthJson` با پیش‌فرض رشتهٔ خالی دارد. مقدار غیرخالی رشتهٔ JSON شامل عرض پیکسلی ستون‌های پوشیده‌شده توسط سلول است؛ آرایه به‌عنوان attribute ذخیره نمی‌شود (ADR-0003 بند ۵). مقدارها هنگام نمایش بررسی می‌شوند: اعداد صحیح نامنفی، حداکثر ۱۰٬۰۰۰ پیکسل، حداکثر ۱٬۰۰۰ ستون. رشتهٔ خالی یعنی اندازهٔ خودکار.

نسخهٔ schema از ۳ به ۴ افزایش یافت. فایل طلایی تازهٔ `packages/schema/fixtures/sv4/tableColumnWidths.json` جدول RTL با سلول ادغام‌شده را ثبت می‌کند؛ فایل‌های طلایی نسخه‌های قبلی بازنویسی نشده‌اند. کلاینت‌های قدیمی طبق قاعدهٔ موجود `max_sv` باید سند جدید را برای ویرایش باز نکنند؛ این تغییر باید همراه به‌روزرسانی وب و دسکتاپ عرضه شود. دادهٔ قدیمی هنگام خواندن همان اندازهٔ خودکار را دارد و به مهاجرت مخرب نیاز ندارد.

رابط وب کنترل درگ نسخهٔ مرجع را به کار می‌برد: مرز داخلی عرض دو ستون را جابه‌جا می‌کند، مرز انتهایی عرض جدول را تغییر می‌دهد، و دوبار کلیک اندازه‌های ذخیره‌شده را پاک می‌کند. جهت RTL و LTR هر دو پشتیبانی می‌شوند. قرارداد wire و envelope تغییری نکرده است.

بلوک جداکننده (`horizontalRule`) هم در همین تغییر منتشرنشدهٔ SV 4 به‌صورت افزایشی بازگشت. فایل طلایی `sv4/divider.json` یک جداکننده بین دو پاراگراف را ثبت می‌کند.
