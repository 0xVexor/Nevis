# زبان طراحی و قرارداد ادامهٔ UI نویس

مرجع تصمیم‌های این سند: گفت‌وگوی طراحی تا ۲ نوامبر ۲۰۲۶. نمونهٔ Settings تأییدشده مرجع بصری است؛ نه ترکیبی از UI قدیمی و نمونه‌های مقایسه‌ای. مسیر اجرایی نمونه: `spike/tiptap/settings-preview.html`.

## هدف و مرز تغییرات

لایهٔ نمایش به یک سیستم قابل استفاده در چند برنامه تبدیل می‌شود. منطق اسناد، ذخیره‌سازی، ویرایشگر، بکاپ، اتصال AI و سایر قابلیت‌ها حفظ می‌شوند. مهاجرت بخش‌به‌بخش است؛ هر بخش جدید به سرویس واقعی متصل می‌شود و ظاهر منسوخ همان بخش حذف می‌شود. ساخت یک پوستهٔ موازی با overrideهای دائمی هدف نیست.

## قرارداد بصری

- حس کلی: آرام، دقیق، سبک و مناسب مطالعه و کار طولانی؛ سطح‌های تخت و مرزبندی ظریف، با رنگ تأکیدی محدود.
- لوگوی مرجع: پر در `src/settings-ui/WorkspaceMark.tsx`. لوگو و هویت فضای کار بالاترین بخش ناوبری‌اند؛ نوار Back/Home/Settings نباید بالای آن قرار بگیرد.
- تنظیمات قدیمی Style، Color strength، Sidebar glass و Main panel glass در ظاهر جدید نمایش داده نمی‌شوند. فیلدهای ذخیره‌شدهٔ قدیمی فعلاً برای سازگاری باقی می‌مانند.
- رنگ، فاصله، اندازه، گوشه و حرکت از `src/design-system/tokens.css` می‌آیند؛ ویژگی‌ها رنگ و سایهٔ مستقل نسازند.
- رنگ تأکیدی پیش‌فرض `#087f74`؛ حالت روشن و تاریک و accent انتخابی کاربر پشتیبانی شوند. سایه عمدتاً برای سطوح شناور است.
- اندازهٔ متن رابط ۱۴، توضیح ۱۲/۱۳، عنوان بخش ۲۰ و عنوان اصلی ۳۲ پیکسل است. اندازهٔ متن ویرایشگر مستقل از اندازهٔ رابط باقی بماند.
- فونت‌های پایه Instrument Sans و Vazirmatn؛ فونت‌های تخصصی متن و کد از توکن‌های موجود. ترجیحات واقعی فونت کاربر حفظ شوند.
- فاصله‌ها روی شبکهٔ ۴ پیکسل؛ ارتفاع کنترل معمول ۳۶ و کوچک ۲۸؛ شعاع پیش‌فرض کوچک/معمول/بزرگ ۷/۱۰/۱۴، قابل تنظیم با ترجیحات موجود.
- شمارندهٔ ناوبری عدد داخل دایرهٔ توخالی است. آیکون، تیک، plus و chevron از SVG و کامپوننت مشترک بیایند؛ کاراکتر متنی جایگزین آن‌ها نشود.
- Dropdown و Menu مشترک جای select بومی؛ حالت focus، disabled، selected و pressed باید مشخص باشند.
- جهت رابط و جهت متن مستقل‌اند. CSS با logical properties و متن‌ها با `t()`؛ فارسی، انگلیسی و محتوای ترکیبی در قرارداد طراحی قرار دارند.

## حرکت و تعامل

توکن‌های حرکت مرجع‌اند: سریع ۱۲۰ و پایه ۲۲۰ میلی‌ثانیه، easing برابر `cubic-bezier(.22,1,.36,1)`. حرکت باید پیوستگی تعامل را توضیح دهد. کلیک Settings نباید دکمه را جابه‌جا یا با New page هم‌پوشان کند. reduced motion رعایت شود. یکپارچه‌سازی کامل چرخهٔ ورود/خروج و layout با Motion هنوز انجام نشده است.

در Icons only فقط مقصدهای اصلی ناوبری نمایش داده می‌شوند؛ Pages، Favorites، Tags و Saved searches پنهان‌اند. هاور یا focus روی لوگو سایدبار کامل را موقتاً روی محتوا باز می‌کند، بدون تغییر ترجیح ذخیره‌شده و بدون جابه‌جایی عرض محتوا؛ خروج از سایدبار آن را جمع می‌کند.

New page یک قابلیت تک‌عملی نیست: عملیات و منوی واقعی آن از پروژهٔ موجود استخراج و حفظ شود. سایدبار Default/Compact/Icons سه حالت متمایز دارد؛ Compact عنوان‌ها را نگه می‌دارد، Icons آن‌ها را پنهان می‌کند. پیش‌نمایش Settings باید هندسه و اجزای همین رفتار را بازنمایی کند.

شورتکات‌ها بر پایهٔ کلید فیزیکی `event.code` و تفاوت Ctrl/Command باشند، مستقل از زبان کیبورد. قابلیت Change/Reset، تشخیص تداخل و ترجیحات ذخیره‌شده حذف نشوند. ثبت یک شورتکات در UI به معنی اتصال کامل آن به فرمان اجرایی نیست؛ وضعیت اتصال در سند تحویل آمده است.

## لایه‌های کد

۱. توکن‌ها و کنترل‌های عمومی: `src/design-system/`، بدون وابستگی به سرویس‌های نویس.
۲. الگوهای عمومی تنظیمات: `Preferences.tsx` و `preferences.css`؛ مقدار و callback می‌گیرند.
۳. ترکیب محصول: `src/settings-ui/` و `design-system/areas/preferences-workspace.css`.
۴. اتصال به قابلیت واقعی: `src/SettingsPage.tsx` و سرویس‌های موجود.
۵. سناریوی نمایشی: `src/previews/settings/`؛ بکاپ و AI نمایشی جای سرویس واقعی را نگیرند.

این تفکیک شروع شده؛ هنوز یک پکیج مستقل و کامل برای برنامهٔ دوم نداریم. استخراج پکیج بعد از اثبات استفادهٔ دوم انجام شود.

## ترتیب ادامه

Settings مرجع ثابت می‌ماند. مرحلهٔ بعد پوستهٔ اصلی است: سایدبار، هویت و لوگو، جست‌وجو، New page چندعملی و نوار بالای محتوا. سپس Home، قاب صفحه و کاور/آیکون، دیتابیس، فلش‌کارت و گراف، و ابزارهای ویرایشگر/Reader. هر مرحله ابتدا نمونهٔ قابل بررسی و سپس اتصال کامل به منطق اصلی داشته باشد.

جزئیات انتقال و دستور آمادهٔ چت بعدی: [راهنمای ادامه](ui-handoff.fa.md).
